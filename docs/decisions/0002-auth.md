# ADR 0002 — Custom NestJS auth (not Clerk/Auth0)

**Status:** Accepted  
**Date:** 2026-09-17

## Context

Phase 1 needs email/password, Google, Apple, TOTP, rotating refresh tokens, and session revocation. The stack ADR already rejected hosted auth.

## Decision

- Custom NestJS auth against Prisma `User` / `Session`.
- argon2id for passwords (faster parameters only when `NODE_ENV=test`).
- HS256 JWTs for access tokens; opaque hashed refresh tokens in Postgres.
- User access, admin access, and short-lived purpose tokens (2FA challenge, OAuth state, OAuth setup) use different secrets: `JWT_ACCESS_SECRET`, `JWT_ADMIN_SECRET`, and `JWT_PURPOSE_SECRET`. Each must be at least 32 characters and distinct from the others. The process exits before it listens when that check fails.
- A token's `kid` is the first 16 hex characters of SHA-256 of the signing secret. Verification accepts that key, or the matching `JWT_*_SECRET_PREVIOUS` during a rotation. Tokens with no `kid` still verify against the current secret and then the previous one, so replacing a secret does not drop sessions inside the 15-minute access TTL. Remove the previous secret after that window.
- Filesystem media URLs stay on the current `JWT_ACCESS_SECRET` only. A previous access secret does not keep those URLs valid.
- OAuth is real authorization-code, not a stub. Missing credentials yield 501.
- New OAuth users must still submit handle + date of birth (age gate).

## Consequences

- We own session rotation and 2FA recovery codes.
- HTTP auth caches the session and suspension tuple in Redis for at most 60 seconds. Logout, revoke, suspend, and delete drop that cache. Postgres is the fallback when Redis is down.
- Rotating a signing secret means setting `JWT_*_SECRET_PREVIOUS` to the outgoing value and `JWT_*_SECRET` to the new one. On the first deploy that splits the old shared secret, set the admin and purpose previous secrets to that outgoing value for 15 minutes if staff sessions and in-flight OAuth or 2FA challenges should survive. While a previous secret is still set, that old key can still mint tokens for its family.
- Google/Apple buttons stay hidden until `NEXT_PUBLIC_OAUTH_CONFIGURED=true` and the matching API secrets exist.
